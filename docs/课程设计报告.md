## 1 引言

### 1.1 题目简介

本课题面向浙江理工大学信息学院《创新实践》课程，完成一套可运行的影神图问答与评测系统。系统以开源项目 Chat-BlackMyth 的 TinyGraph 为数据层，将《黑神话：悟空》影神图文本建成 Neo4j 知识图谱，在查询期引入规划、双路检索与校验三个角色协同作答，并在同一张图上对照智谱、DeepSeek、通义千问的图谱问答与纯生成表现。

### 1.2 背景与意义

影神图是游戏内的人物、头目与关系说明，结构接近知识条目，但玩家与课程演示仍多用自然语言提问。直接调用大模型时，容易把《西游记》原著常识答成游戏设定，例如将「黑风山土地」讲成小说情节。向量检索只能召回相似段落，对「部下、交手、位于」这类多跳关系不够稳定。

知识图谱把「谁—关系—谁」显式存下来，图上行走可以补全跨条目的关系。微软 GraphRAG 与开源 TinyGraph 已验证「文本→图→检索生成」可行。Chat-BlackMyth 进一步把影神图做成可演示的 GraphRAG，但查询仍是一次局部检索，缺少可解释的多步推理，也缺少跨模型的封闭评测。本课题在其数据层上补齐查询智能体、公平对照与性能看板，使课程设计同时具备可运行系统、可解释路径和可讨论的实验结论。

### 1.3 目标

（1）在 Neo4j 中建成前三章（黑风山、黄风岭、小西天）影神图，实体带向量，关系可按模板走 1～3 步。  
（2）查询期按「规划 → 双路检索 → 成答 → 校验」协作，界面展示子问题、实体、三元组与检索子图。  
（3）图谱只建一次、向量固定智谱，问答切换智谱 / DeepSeek / 千问，对照「图谱问答」与「纯生成」。  
（4）用封闭题集给出正确率、引用覆盖、时延与综合分，并总结「基线越弱、接图谱提升越大」。

## 2 系统详细设计

### 2.1 总体目标与模块划分

系统分为四层：交互层、智能体层、图谱层、评测层。模块划分见图 1 的文字结构。

```
Gradio 网页
  问答页：选择模型 → 图谱问答 ‖ 同模型纯生成（并行）
  性能页：读取评测结果 → 综合排名 / 雷达 / 分项图
        │
模型工厂    智谱 · DeepSeek · 千问
        │
智能体循环  规划器 → 双路检索 → 成答器 → 校验器（最多 4 轮）
        │
TinyGraph   原文邻域检索 + 模板图查询（1～3 步）
        │
Neo4j       实体 / 关系 + embedding-3（建图固定智谱）
```

### 2.2 建图模块：算法与流程

建图沿用 TinyGraph，按角色切块，避免固定字数滑窗把同一人物拆碎。处理流程见图 2。

```
影神图 Markdown
    → 按「影神图角色」切块
    → 对每个新块：抽取实体、抽取三元组
    → MERGE 写入 Neo4j（同名合并）
    → 社区发现（有图数据科学插件则 Leiden，否则单社区回退）
    → 实体描述向量化（embedding-3）
    → 标记文档已加载，支持增量补块
```

**图 2 建图处理流程**

实体节点主要属性：`name`、`description`、`entity_id`、`embedding`、`communityIds`。关系边属性：`name`（关系名）。块与文档记录在本地 `workspace/`，用内容哈希去重，避免重复调用大模型。

图查询不由模型生成任意语句，只使用绑定实体名的模板：从名称包含给定字符串的实体出发，沿无向关系走 1～3 步，返回头、关系、尾。从而保证「模型不能随便写图数据库语句」。

### 2.3 查询智能体：逻辑流程与数据结构

一次提问的控制流程见图 3。这是相对原仓库的核心增量：原项目一次局部检索即生成；本系统把「要想什么、去哪查、答完核不核」拆成四个角色。

```
用户问题
    → 规划器：直接作答 或 追加子问题
    → 双路检索
          关系词（部下、交手、位于、交好…）→ 模板图查询 1～3 步
          生平 / 身份 / 始终拼接 → 原文邻域
    → 成答器：只用证据写 1～2 句通顺中文
    → 校验器：足够则结束；不足则回到规划器（最多 4 轮）
    → 返回：答案、子问题路径、实体、三元组（画检索子图）
```

**图 3 查询期智能体流程**

共享证据集字段见表 2。

**表 2 证据集主要字段**

| 字段 | 含义 |
| --- | --- |
| entities | 命中实体（名、描述、编号） |
| triples | 命中三元组（头、关系、尾） |
| chunks | 原文摘录（截断，过滤「是 / 为」等弱关系） |
| subquestions | 本轮子问题序列 |
| notes | 检索失败等备注 |

成答提示要求：问什么答什么、禁止「证据提到」等过程套话、优先游戏设定而非原著课文。后处理去掉英文题型标签和「证据提到」之后的堆砌，减轻病句。

校验器在完全没有实体、三元组与原文时才判为未知；有证据则根据草稿判断是否还需要追问。

### 2.5 用户界面

界面用 Gradio，两个标签页。

（1）**问答页**：模型单选（智谱 / DeepSeek / 千问）；「连接图谱」默认只连已有 Neo4j，勾选重建才会重新抽实体。左右两栏并行请求：左为智能体图谱问答，右为同模型纯生成。下方为推理过程、检索子图（微软雅黑标注中文）、实体表与三元组表。示例问题包括土地公、白衣秀士、广智广谋等稳题。

（2）**性能对照页**：读取 `eval/results.json`。顶部自动生成综合结论；随后为三家图谱问答的综合排名、雷达画像、相对纯生成的 Hit@1 增益，以及分项柱状图与题型正确率。综合分定义为：

综合分 = 0.45×正确率 + 0.25×图谱引用 + 0.15×答案重叠 + 0.15×速度

速度以三家图谱问答中最快者为 1。权重可调，分项均在表中列出，避免只看一个总分。

## 3 实验结果与讨论

### 3.1 实验条件

- 图谱：前三章 90 角色，Neo4j 中 441 个实体（均有向量）、910 条关系。  
- 问答模型：智谱 `glm-4-flash`、DeepSeek `deepseek-chat`、千问 `qwen3.5-flash`（关闭思考链，避免单次三十秒级推理）。  
- 建图与检索向量：始终智谱 `embedding-3`。  
- 题集：14 题，含事实、多跳关系、对比；关键词与别名匹配计算 Hit@1。  
- 对照：每家模型「图谱问答」与「纯生成」共六路。

### 3.2 结果展示

**表 4 六路评测汇总**

| 模型 / 模式 | Hit@1 | 引用覆盖 | 平均时延 / s |
| --- | --- | --- | --- |
| 智谱 图谱问答 | 0.64 | 0.70 | 4.3 |
| 智谱 纯生成 | 0.43 | 0.88 | 12.3 |
| DeepSeek 图谱问答 | 0.79 | 0.86 | 3.9 |
| DeepSeek 纯生成 | 0.71 | 0.92 | 2.7 |
| 千问 图谱问答 | 0.79 | 0.93 | 6.6 |
| 千问 纯生成 | 0.64 | 0.87 | 7.5 |

**表 5 三家图谱问答综合能力（仅 GraphRAG 智能体）**

| 排名 | 智能体 | 综合分 | 正确率 | 图谱引用 | 相对纯生成 Hit@1 提升 |
| --- | --- | --- | --- | --- | --- |
| 1 | DeepSeek | 0.76 | 0.79 | 0.86 | +0.07 |
| 2 | 千问 | 0.72 | 0.79 | 0.93 | +0.14 |
| 3 | 智谱 | 0.67 | 0.64 | 0.70 | +0.21 |

页面「性能对照」可加载与表 4、表 5 一致的柱状图、雷达图与综合结论文案。问答页在「黑风山土地是谁」一类题目上，左侧能约束到游戏土地公，右侧纯生成常讲原著；检索子图显示本轮实体与关系。

### 3.3 结果分析与讨论

（1）**图谱对弱模型帮助更大。** 智谱纯生成 Hit@1 仅 0.43，接图谱后 0.64，提升 21 个百分点；千问提升 14 个百分点；最强基线 DeepSeek 从 0.71 到 0.79，仅 7 个百分点。弱模型更容易把原著常识当成游戏设定，图上的实体名和原文摘录起到约束作用。因此不能只用「DeepSeek 纯生成已经 0.71、智谱图谱问答只有 0.64」否定图谱：跨模型比的是综合能力，同一模型「有图 / 无图」才说明检索是否有效。

（2）**正确率天花板由较强聊天模型决定。** 图谱问答下 DeepSeek 与千问并列 0.79，智谱 0.64。综合分 DeepSeek 第一，因其速度与正确率都高；千问引用覆盖最高（0.93），答案更常点名影神图实体。

（3）**速度。** 左右栏已并行，页面等待接近较慢一侧。千问默认思考链曾导致单次约 30 秒、多轮到两分钟，关闭思考后图谱问答约 6.6 秒，与另外两家同一量级。DeepSeek 纯生成最快（2.7 秒）。

（4）**失败案例。** 「黄眉是谁、第几章、在哪」曾被答成「龟将部下、苦海、第二章」。设定上黄眉是第三章小西天妖王，据点小雷音寺，在苦海与龟蛇二将交手而非部下。图中弱边「黄眉—与—龟将」「龟将—位于—苦海」被模型脑补成隶属与章数。说明模板查询仍会带回「是 / 与 / 人物」一类空边。演示宜用土地公、白衣秀士、广智广谋；黄眉作为局限案例在报告中保留。

（5）**成答质量。** 早期存在「证据提到……」的分号堆砌。收紧成答提示并过滤过程套话后，土地归属类问题可稳定答成「黑风山土地管黑风山，黄风岭土地管黄风岭」，不再夹带灵吉菩萨等无关实体。这提升的是语句质量，封闭集 Hit@1 未因这一改动全部重跑。

（6）**题量。** 14 题偏少，结论表述为趋势而非精确到百分点的「刷分」。同时给出引用覆盖与时延，避免只看一个正确率。

## 4 结论

本课程设计在 Chat-BlackMyth / TinyGraph 数据层上，完成了可运行的影神图多智能体问答与跨模型评测。相对原开源项目，查询由一次局部生成改为规划、双路检索、成答、校验的协作；图跳转由程序模板约束；同一张图上比较三家大模型；并用封闭集得到「基线越弱、图谱提升越大」的实验结论。

工作仍有限：演示库为前三章而非全量六章；评测 14 题；社区报告未作为主路径；弱关系边会带来如黄眉一类事实错误；Grok 未进入数字。后续可过滤空边、扩大封闭集、在同一流水线上补全量入库。

对课程目标而言，小组完成了选题、可行性分析、系统实现、对照实验与文档，源码见 GitHub，满足任务书中「可运行程序、设计报告、演示」的交付要求。

```python
def ask(query, graph, llm, max_rounds=4):
    evidence = Evidence()
    queue = seed_subquestions(query)
    rounds, draft, mark = 0, "", "NEED"
    while rounds < max_rounds:
        rounds += 1
        sub = queue.pop(0) if queue else query
        retrieve(sub, graph, evidence)
        draft = clean_answer(
            llm.predict(SYNTH_PROMPT.format(query=query, evidence=evidence.as_prompt()))
        )
        mark = verify(query, draft, evidence, llm)
        if mark in ("OK", "UNKNOWN"):
            break
        nxt = plan(query, evidence, llm, rounds, max_rounds)
        if nxt.startswith("FOLLOWUP:"):
            queue.append(nxt.split(":", 1)[1].strip())
        elif nxt == "ANSWER":
            break
    return {"answer": draft, "path": evidence.subquestions,
            "cites": [...], "triples": evidence.triples[:20], ...}
```
