## 1. 目标

在同一套影神图知识图谱上，切换不同大模型（智谱 glm-4-flash、DeepSeek），对照「多智能体 GraphRAG」与「纯生成」，用 Hit@1、引用覆盖和时延说明图谱检索的增益。

## 2. 系统架构

```
Gradio
  问答 Tab：选 LLM → agents.loop.ask() | llm.predict()
  性能 Tab：读 eval/results.json（柱状图 + 表）
        │
graphrag/llm/factory.py   zhipu | deepseek | grok
        │
agents/  Planner → Dual-Retrieval → Verifier（最多 4 轮）
        │
TinyGraph  local 邻域检索 + graph_query（1–3 跳模板 Cypher）
        │
Neo4j Entity/Relationship + embedding-3（建图固定智谱）
```

图谱只建一次。换模型只换问答 LLM，不换索引，保证对比公平。

## 3. 算法要点

1. **建图**：样例 Markdown 分块 → 抽实体/三元组 → 写入 Neo4j → Leiden 社区（无 GDS 则单社区回退）→ 节点 embedding。
2. **Planner**：单跳直接作答；多跳按证据缺口生成子问题。
3. **Dual-Retrieval**：关系类问题走 `graph_query`；生平/外形走 `build_local_query_context`。
4. **Verifier**：证据不足则声明「影神图未记载」，避免把原著常识当成游戏设定。

禁止模型直接执行任意 Cypher，只使用按实体名绑定的 1–3 跳模板。

## 4. 实验

封闭集 14 题，图谱为前三章（441 实体 / 910 边）。Hit@1 按标准答案分句与别名匹配。

| 模型 / 模式 | Hit@1 | 引用覆盖 | 平均时延 |
| --- | --- | --- | --- |
| 智谱 GraphRAG | **0.79** | 0.87 | 4.0 s |
| 智谱 纯生成 | 0.36 | 0.88 | 12.5 s |
| DeepSeek GraphRAG | **0.93** | 1.00 | 3.4 s |
| DeepSeek 纯生成 | 0.64 | 0.92 | 2.5 s |

结论：

1. 同一模型下，GraphRAG 相对纯生成 Hit@1 约提升 35 个百分点。
2. GraphRAG 模式下 DeepSeek 正确率最高；关系题（hop）两家 GraphRAG 均为满分。
3. 纯生成仍易混入原著常识；图谱路径能约束到游戏设定。二郎神、黑熊精等事实题依赖原文块，已改为始终拼接 local context。

逐题数据见 `eval/results.json`。页面「性能」Tab 可直接加载柱状图。
